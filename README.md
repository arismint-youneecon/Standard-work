# QR 표준작업 앱 — 설치 가이드 (파일럿)

작업자가 설비 QR을 찍으면 그 공정의 표준작업·자주검사·안전·품질·이상조치를 휴대폰으로 보고,
관리자는 PC 컨트롤타워에서 내용을 등록·게시하는 시스템입니다.

```
qr-standard-work/
├─ config.js              ← Supabase 주소/키 (여기만 수정)
├─ worker/index.html      ← 작업자 앱 (휴대폰, QR로 진입)
├─ worker/i18n.js         ← 작업자 앱 화면 문구 11개 언어
├─ admin/index.html       ← 컨트롤타워 (PC)
└─ supabase/
   ├─ schema.sql          ← DB 테이블·권한·함수 (1회 실행)
   ├─ seed_sample.sql     ← (선택) 샘플 라인/설비/표준
   └─ functions/translate-standard/index.ts  ← 자동 번역 (Edge Function, Claude API)
```

구성: 정적 HTML 2개 (GitHub Pages 등 아무 정적 호스팅) + Supabase (DB·인증·파일저장·권한).
서버 코드 없음. 외부 접속 도메인은 호스팅 주소와 `*.supabase.co` 두 개뿐 (라이브러리는 `vendor/`에 동봉). 유지보수는 `config.js`와 HTML 파일 2개, SQL 1개가 전부입니다.

## 1. Supabase 프로젝트 만들기 (10분)

1. https://supabase.com 가입 → **New project** (Region: Northeast Asia (Seoul) 권장)
2. 좌측 **SQL Editor** → `supabase/schema.sql` 전체 붙여넣기 → **Run**
   - 테이블, 권한(RLS), 함수, 파일 버킷(`media`)이 한 번에 만들어집니다.
3. (선택) `supabase/seed_sample.sql` 도 같은 방법으로 실행 → 샘플 라인·설비·표준이 들어갑니다.
4. **Authentication → Sign In / Providers**
   - **Email**: 켜기. **Confirm email**: 끄기 (컨트롤타워에서 계정을 만들면 바로 로그인되게)
   - **Anonymous sign-ins**: 켜기 ← 작업자 앱이 사용합니다 (작업자는 이메일/비번 없음)
5. **Authentication → Users → Add user** 로 본인 이메일 계정 생성 (비밀번호 설정, Auto Confirm 체크)
6. SQL Editor 에서 본인을 관리자로 등록:
   ```sql
   insert into profiles (id, name, role)
   select id, '서성목', 'admin' from auth.users where email = '본인이메일@forvia.com';
   ```
7. **API Keys** 화면에서 `Project URL` 과 **Publishable key**(`sb_publishable_…`, 구 anon key) 복사 → `config.js` 에 입력
   - `Secret key`(`sb_secret_…`)는 절대 넣지 마세요. Publishable 키는 공개돼도 괜찮습니다 (권한은 RLS가 막습니다).

## 2. 호스팅 (5분)

GitHub Pages 기준 (기존 FES 8QB 앱과 같은 방식):
1. 새 저장소 생성 (예: `standard-work`) → 폴더 전체 업로드
2. Settings → Pages → Branch `main` / root → Save
3. 주소 확인: `https://<계정>.github.io/standard-work/`
   - 컨트롤타워: `.../standard-work/admin/`
   - 작업자 앱 : `.../standard-work/worker/?eq=설비코드` ← QR에 들어가는 주소

> 저장소는 Private 로 둬도 Pages 는 공개됩니다(GitHub Free). 데이터는 저장소에 없고 전부 Supabase에 있으며
> 세션 없는 사람은 아무것도 볼 수 없으니 HTML이 공개되는 것 자체는 문제 없습니다.

## 2-1. 자동 번역 설정 (다국어가 필요할 때, 10분)

작업자 앱은 한국어·영어·중국어·일본어·베트남어·우즈베크어·러시아어·네팔어·카자흐어·벵골어·프랑스어를 지원합니다.
화면 문구는 이미 11개 언어로 들어 있고, **표준 내용**은 컨트롤타워의 "번역 생성" 버튼으로 자동 번역됩니다(Claude API 사용).

1. Anthropic API 키 발급: https://console.anthropic.com (API Keys)
2. Supabase CLI 설치 후 함수 배포 (Mac 터미널):
   ```bash
   npm install -g supabase
   supabase login
   supabase link --project-ref <프로젝트-ref>        # Project Settings > General 에 있음
   supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
   supabase functions deploy translate-standard       # qr-standard-work 폴더 안에서 실행
   ```
   (CLI 대신 대시보드 Edge Functions 화면에서 코드 붙여넣기 + Secrets 입력도 가능)
3. 선택 설정 (Secrets): `TRANSLATE_MODEL` (기본 claude-sonnet-5-5), `GLOSSARY="너깃=nugget; 급소=key point"` 처럼 용어 고정
4. 사용: 표준 편집 → 한국어로 작성 → **번역 생성 / 갱신** → (필요 시) 언어 선택 후 **검토 · 수정** → 게시
   - 번역은 초안에 저장되고 게시 시 함께 공개됩니다. 한국어 원문을 고치면 "원문이 바뀜" 표시가 뜨니 다시 생성하세요.
   - 번역이 없는 언어를 고른 작업자에게는 한국어가 보이고 "번역 없음" 안내가 뜹니다.
   - 비용: 표준 1개(문장 30~50개) × 10개 언어 ≈ 수십 원. 설비 100개를 전부 번역해도 수천 원 수준.
   - 현장 용어(사내 약어, 부품명)는 첫 몇 개 표준의 번역을 검토해 보고 GLOSSARY 에 넣어 두면 이후 번역이 일관됩니다.

## 3. 첫 사용 순서

1. 컨트롤타워 로그인 → **라인 · 설비**: 공장 → 라인(예: 코드 `GPF`, 이름 `GPF 라인`) → 설비 등록 (설비코드는 `GPF-OP10`처럼 라인코드-공정으로, QR에 박히므로 한 번 정하면 유지)
   - 작업자 앱 상단에 라인 이름이 노란 배지로 크게 표시됩니다. 40개 라인으로 확대해도 라인만 추가하면 됩니다.
2. **표준 편집**: 설비 선택 → 5개 탭(안전 → 표준작업 → 자주검사 → 품질 → 이상조치) 입력 → 초안 저장 → **게시**
   - 사진/영상은 "업로드" 버튼으로 PC에서 바로 올라갑니다.
   - 표준작업 탭: 맨 위 "전체 공정 작업 영상(처음~끝)" 1개, 그 아래 작업 순서 텍스트 + 각 단계 옆 참고 사진 1장. 구간별 추가 영상은 선택.
   - 작업자 앱은 **안전 탭이 가장 먼저** 열립니다.
3. **QR코드 출력**: 라인 선택 → 인쇄 → 코팅 후 설비 부착
4. **작업자 · 접속코드**: 이름만 입력 → 8자리 코드 발급 → 작업자에게 전달 (사번 없음. 동명이인은 '김민수(협력사명)'처럼 구분)
5. 작업자: 휴대폰 카메라로 QR 촬영 → (최초 1회) 코드 입력 → 표준 열람

## 3-0. 대시보드

상단 카드 6개(등록 설비, 표준 게시 완성도, 5개 섹션 완료 설비, 게시 대기 초안, 세션 활성 작업자, 최근 7일 열람)는 모두 클릭하면 해당 상세로 이동합니다.
**표준 게시 매트릭스**는 설비 × 섹션 칸을 게시(초록 ✓ vN)/초안(노랑 ●)/없음(회색 —)으로 보여 주고 라인별 완성도 막대가 붙습니다. 칸을 누르면 그 설비·섹션 편집 화면이 바로 열립니다. 🌐는 10개 언어 번역이 끝난 게시본.
하단에는 작업자 세션 상태(활성/만료/차단 비율, 미사용 접속코드, 라인별 등록 인원), 게시 대기 초안(오래된 순, 7일 넘으면 경고), 최근 게시 이력과 번역 완료율이 있습니다.

### 라인별 표준 열람 현황

라인마다 등록 작업자 수, 기간(오늘/7일/30일) 내 열람한 작업자 수와 비율, 미열람 인원, QR 스캔 수, 섹션별(안전/표준작업/자주검사/품질/이상조치) 열람 수가 나옵니다.
"설비별 보기"를 누르면 그 라인의 설비별 열람 수와 **미열람 작업자 명단**(사번·이름·마지막 열람)이 펼쳐집니다.
표 아래에 그래프 3개가 있습니다: 라인별 열람 작업자 비율(가로 막대), 섹션별 열람 수(세로 막대), 일별 열람 추이(QR 스캔·섹션 열람 선 그래프). 라인을 "설비별 보기"로 열면 그래프도 그 라인 기준으로 바뀌고, 마우스를 올리면 값이 뜹니다.
라인 책임자는 담당 라인만, 관리자는 전체가 보입니다. 교육 이수 확인이나 "표준 개정 후 누가 아직 안 봤는지" 점검에 쓰면 됩니다.

## 3-1. 앱 문구 · 설정 바꾸기 (관리자)

컨트롤타워 **앱 문구 · 설정** 메뉴에서 코드 수정 없이 바꿀 수 있습니다.
- 기본 설정: 앱 이름, 공장명(작업자 앱 상단), 세션 유효 시간(기본 12시간)
- 화면 문구: 탭 이름·섹션 제목·안내문·오류 메시지 전부, 11개 언어별. 비워 두면 기본 문구(`worker/i18n.js`)가 쓰입니다.
- "한국어 수정분 → 10개 언어 자동 번역" 버튼으로 수정한 한국어 문구를 한 번에 번역 (Edge Function 필요, 2-1 참고)
- 저장 즉시 DB에 반영되고, 작업자는 앱을 다음에 열 때(QR 촬영 시) 새 문구를 봅니다. 별도 배포 작업 없음.

## 4. 권한 체계

| 역할 | 할 수 있는 것 |
|---|---|
| 관리자 (admin) | 전체 라인, 편집자 계정 관리, 변경 이력 열람 |
| 라인 책임자 (line_manager) | 담당 라인의 설비 등록, 표준 작성·**게시**, 접속코드 발급 |
| 작성자 (author) | 담당 라인의 표준 **초안**만 작성 (게시 불가) |
| 작업자 | 유효 세션(QR 스캔 후 12시간) 동안 게시본 열람만 |
| + 삭제 권한 (can_delete) | 공장·라인·설비 **영구 삭제**. 역할과 별개의 플래그로, 관리자라도 체크돼 있어야 삭제 가능. 삭제 시 코드 재입력 필요, 변경 이력에 기록 |

- 편집자 계정은 컨트롤타워 **편집자 계정** 메뉴에서 추가하고, 담당 라인을 체크합니다. 삭제 권한도 같은 화면에서 체크합니다.
- 추가·수정은 역할대로 자유롭게, 삭제는 삭제 권한자만. 라인 삭제 시 그 라인의 설비·표준(이전 버전 포함)이 함께 지워지므로, 잠시 안 쓰는 설비는 삭제 대신 "비활성"을 쓰세요.
- 다른 라인으로 확대할 때: 라인 추가 → 그 라인 책임자 계정 추가 → 담당 라인 체크. 끝.
- 권한은 화면이 아니라 DB(RLS)에서 막기 때문에, HTML을 뜯어봐도 권한 밖 데이터는 나오지 않습니다.

## 5. 세션/접속 동작

- 작업자는 최초 1회 접속코드로 **그 휴대폰**을 등록합니다 (코드는 1회용).
- QR을 찍을 때마다 12시간 유효 세션이 갱신됩니다. 12시간이 지나면 "QR코드를 다시 촬영해 주세요" 화면만 나옵니다.
- 주소창에 `?eq=` 가 남지 않도록 지워지므로, 북마크/새로고침으로는 세션이 연장되지 않습니다.
- 휴대폰을 바꾸거나 앱 데이터를 지우면 새 코드가 필요합니다. 퇴사자는 작업자 목록에서 **차단**.
- (보류한 사항) QR 인쇄물 사진으로 외부에서 재스캔하는 것은 이 구조로는 막지 못합니다. 필요해지면
  사내 Wi-Fi IP 제한 또는 위치 확인을 `register_scan` 함수에 추가하면 됩니다.

## 6. 파일(영상·사진) 한도

- Supabase **Free**: 파일당 최대 50MB, 전체 1GB, 월 전송량 5GB, **1주일 미사용 시 프로젝트 일시정지**
- Supabase **Pro ($25/월)**: 파일당 500GB, 전체 100GB, 전송 250GB — 실제 운영은 Pro 권장
- 영상은 공정당 1~3분, 720p, H.264 mp4 로 압축해서 올리면 20~50MB 선에서 끝납니다.
  (아이폰 녹화 원본은 1분에 100MB 이상이라 그대로 올리면 금방 한도에 닿습니다.)
- 파일 한도를 올리려면 Supabase → Storage → Settings → Global file size limit.

## 7. 데이터 구조 (참고)

- `plants > lines > equipment` : 공장/라인/설비
- `standards` : 설비 × 섹션 × 버전. `draft → published → archived`. 게시할 때마다 버전이 올라가고 이전 버전은 보관됩니다.
- `profiles`, `profile_lines` : 편집자와 담당 라인
- `access_codes`, `workers` : 접속코드와 등록된 휴대폰(세션 만료 시각 포함)
- `app_settings`, `app_texts` : 앱 이름·공장명·세션 시간, 화면 문구 덮어쓰기(키×언어)
- `view_logs` : 누가 언제 어느 설비의 어느 섹션을 봤는지 / `audit_log` : 누가 무엇을 바꿨는지
- 섹션별 내용은 JSON 이며 구조는 `admin/index.html` 의 `SCHEMA` 와 `worker/index.html` 의 렌더러가 1:1로 맞춰져 있습니다.
